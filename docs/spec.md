# akapen 仕様（たたき台）

日本で暮らす外国人が、生活の場面（電話での予約、役所への問い合わせなど）を、本番の前に声で予行演習するアプリ。
学習用の会話相手ではなく、**本番を通すための予行演習とカンペ**として作る。

> 印（**未決**）の所は作り手が決める。

## 1. 流れ

1. 場面を選ぶ → 2. 予行演習（声） → 3. 赤ペン → 4. 本番のカンペ

## 2. 場面の選び方

- データ: yasashii-refs の `data/seikatsu-cando.jsonl`（kind が「生活Can do」785行、「生活・文化・社会的情報」145行）。
- 予行演習に使うのは、`activity` が「やり取り」の Can do のうち、相手と声で話すもの。最初は「電話」が出てくるものから選ぶ。
- 期限までに作り込む場面（案）:

| 通番 | 場面 | レベル | 扱い |
| --- | --- | --- | --- |
| 588 | 粗大ごみの回収を電話で頼む | A2 | デモの主な場面 |
| 125 | レストランなどの予約を電話でする | A2 | 2つ目 |
| 160 | タクシーの予約を電話でする | A2 | 3つ目 |
| 6 | 病院や歯医者の予約を電話でする | A2 | きっかけの場面。受付として名前・日時・用件を聞くだけ |

- 画面は「大分類 → 小分類 → Can do」で選ぶ。Can do の文はそのまま見せず、場面の名前（事例２ `case2` など）を見せる。**未決**: 母語での場面名を出すか。
- 安全や生命にかかわる場面（110番・119番、陣痛、医療相談など: 通番 4・46・51・72・216 など）は予行演習にしない。その場面を選ぼうとしたら、多言語の窓口・情報を案内する。
- 生活Can do は「できるようにならなければならない一覧」ではない、と画面に書く。

## 3. 相手役（Claude）

- 場面ごとに、相手の役（受付・店員など）・聞くこと（名前・電話番号・日時・品目など）・本番で起きやすいこと（例: 冷蔵庫は粗大ごみで受けない）を「場面カード」として持つ。最初の場面は手で書く。Claude で下書きし、作り手が確かめる。
- ふるまい:
  - 本物の受付のように話す（敬語・決まった言い方を使う）。学習者に合わせて「やさしい日本語」にはしない。速さだけ、Can do の条件（「ゆっくりとはっきりと話されれば」）に合わせて選べる。
  - 聞き返されたら、本物の受付がするように言い直す。
  - 途中で日本語を教えない・直さない（赤ペンは後で別に入れる）。
  - 用件が終わる（または話が止まる）と終える。
  - 医療の助言はしない。病院の受付役は名前・日時・用件を聞くだけ。
- 文字起こし: ElevenLabs Scribe。学習者の誤りと言いよどみを直さずに残す（確かめ: `docs/plan.md` の 1）。
- 相手役の声: ElevenLabs の読み上げ（第一候補）か、ブラウザの読み上げ。

## 4. 赤ペン

相手役とは別の呼び出しにする（Medkit に倣い、演じる役と、指針に照らして見る役を分ける）。

- 入力: 文字起こし（言いよどみつき）、場面カード、Can do の文。
- 見る順番（**未決**: 作り手が直す）:
  1. 用件が変わる・止まる（例:「だいじょうぶです」が「はい」か「いいえ」か分からない）
  2. 相手の言葉を聞き取れていない（聞き返していない）
  3. 失礼・ぶっきらぼうに聞こえそう
  4. 文法・語の誤り（伝わったものは「今は直さなくていい」に入れる）
- 言いよどみ・言い直しは直さない。
- 本番までに直すことは、多くても3つに絞る。伝わった所も示す（**未決**: ○を付けるか）。
- 出力（構造化出力）: 赤ペンごとに、種類・どの発話か（引用）・なぜ困るか・次の言い方・優先順。
- 見せ方: 3案を作った（案A 添削・案B 相手の耳・案C 直すのは2つ）。**未決**。

## 5. 本番のカンペ

本番の電話や窓口で見る1枚のメモ。

- 聞かれること（相手の言い方と、その意味）
- 言うこと（自分の答え。赤ペンで直した言い方が入る）
- 困ったときの言い方（もう一度お願いします、ゆっくりお願いします、など）
- 前もって知っておくこと: その Can do の小分類 `minor_no` につながる「生活・文化・社会的情報」から選ぶ。例: 粗大ごみ（ごみの出し方）。
- その人の言語を並べる（**未決**: 最初に出す言語。例: 中国語・ベトナム語・英語・やさしい日本語）。
- 画面のほか、印刷やスマホで見やすい形にする。

## 6. 評価

MaestrIA に倣い、評価を先に作る。

- 架空の予行演習の文字起こしを用意する（場面ごとに数本。誤りの種類を変える）。作り手が赤ペンを入れる（正解）。
- Claude の赤ペンと比べる: 作り手が入れた所を Claude も入れたか（拾えた割合）、Claude だけが入れた所（入れすぎ）、上位3つの順番が合うか。
- 作り手が「直さなくていい」とした所に、Claude が赤を入れていないか（言いよどみ・伝わった文法の誤り）。
- 結果は docs/ に数字で書き、デモ動画でも見せる。
- 実在の人の録音・文字起こしは `local/`（git 管理外）でだけ使い、リポジトリには数字だけを書く。

## 7. 作り

- gyokan と同じ: Vite+ / Vue 3 / TypeScript / Cloudflare Workers。
- Worker: `/api/scribe`（ElevenLabs へ）、`/api/turn`（相手役）、`/api/akapen`（赤ペン）、`/api/kanpe`（カンペ）。
- Claude API: 構造化出力。モデルは gyokan と同じものから始める。
- キー: Claude は `ANTHROPIC_API_KEY`。ElevenLabs・Cloudflare は環境のネットワークシークレット。リポジトリに入れない。

## 8. 出典

- 文化審議会国語分科会「地域における日本語教育の在り方について」（報告）別冊「日本語教育の参照枠」に基づく「生活Can do」一覧（令和4年11月29日、文化庁 https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/hokoku/）を加工して作成（PDL1.0）。
