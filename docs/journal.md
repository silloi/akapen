# 作業の記録（デモ動画の素材）

受賞者のインタビューにあった「毎日の記録が、あとで動画の物語になる」にならって、起きたこと・つまずき・発見を日ごとに残す。個人の情報は書かない。

## 11/5（木）

- 企画の要点を受け取る。文化庁の「生活Can do」から、電話でのやり取りの場面を選び、Claude が相手役になり、赤ペンを入れ、本番のカンペを作る、という流れ。
- 赤ペンの見せ方を3案（添削・相手の耳・直すのは2つ）にして、作り手が「添削」を土台に選んだ。
- つまずき: Claude のキーが環境変数では届かず、夜のあいだ Claude を呼ぶ確かめができなかった。ElevenLabs のキーも、ヘッダーの形と権限で2回つまずいた。
- 発見: ElevenLabs の文字起こし（Scribe）は、言いよどみを残す一方で、学習者の文法の誤りを正しい形に直してしまうことがある（「来るます」→「来ます」）。赤ペンは「文字に残った誤り」しか見られない。
- 合成音声で、英語話者の声に日本語を読ませると、住所と電話番号が大きく崩れた。相手役は本物の受付のように聞き返した。

## 11/6（金）

- 作り手が最初の通しの動画を見て、「ユーザー体験が整理されている」と驚いた。設計で入れなかったこと（会話の途中で直さない、翻訳ボタンを置かない、発音を採点しない）を共有した。
- 文字起こしに場面の語（`keyterms`）を渡すと、建物名の聞き違いが消えた。
- カンペを QR でスマホに送り、本番用の大きい文字の画面で開けるようにした。
- 「直した言い方でもう一度練習する」: 2回目の赤ペンで、前回のつまずきが直せたかを ○△ で示す。
- 事例調査: 国内外の受電 AI と、人を訓練する AI ロールプレイの型を調べた。一番の発見は、受付 AI が「bot が間違えないため」に文書化した規則（番号を1桁ずつ復唱、二段階の聞き返し）が、そのまま「人が間違えないためのカンペ」になること。非母語話者を設計の対象にした製品は見つからなかった。
- 作り手の判断: 規則で固めすぎない。「本番が通る率」は主張せず、赤ペンの質を教師の判断と比べて測る。役所の場面では、相手役がやさしい日本語に切り替えてよい（多くの自治体が電話応対でしていること）。
- 作り手のフィードバック: 「201号室」が「ニセンイチ」と読まれた → 番号は1桁ずつカタカナにして読み上げる。学習者の声は非母語話者らしい方がよい。カンペが長すぎる → 15〜18行に。
- 作り手のアイデア: 日本に溶け込んで暮らそうとしている外国人住民は「日本語上手ですね」と言われるのを嫌がる。動画のフックに。
- 相手の様子（ていねい・ふつう・急いでいる・気むずかしい）を、開始のたびにランダムに引くようにした。本番の相手は選べない。
- 場面を4から50に広げた。Claude に下書きさせ、別の検査役が決まった項目で見て、通らなければ1回だけ書き直す。検査役は「実在しそうな市外局番の電話番号」「Can do の範囲を超えた聞くこと」「不自然な敬語」をつかまえた。1件（150 銀行の申込書の書き方）は2回とも通らず入れなかった。窓口（対面）の場面では、相手役が「在留カードを拝見してもよろしいですか」と書類を見る動きをし、違う紙を見せられて「今日は手続きができません」と返した。
- 下書きの場面を3つ通して確かめた（病院の受付・上司への電話・駅の窓口）。病院の受付は保険証と問診票の受け渡しだけで、症状に踏み込まなかった。上司は敬語でなく上司らしい話し方（「確認した？」）になり、駅員は乗り換えのホームまで案内した。赤ペンは3つとも「分からない語に『はい』と答えた」「名詞だけの質問（お金は？ ペンは？）」を取り、聞き返せた所に ○ を付けた。
- 作り手の指摘: 「なぜ困るか」「次はこう言う」「全体の一言」は AI っぽい日本語。問いかけ（「どこでつまずく？」「次はどう言う？」）に変え、まとめは「先生から」にした。
- 多言語化。作り手の方針: まず自分たちのリソース（やさしい日本語ガイドラインの書き換え例）で **やさしい日本語** に書き換え、それを元に各言語に訳す。行政語・敬語・長い文を先にほどいておくと、9言語に同じ意味で渡せる。やさしい日本語そのものも画面の言語の1つにした。
- 作り手の指摘: ベトナム語の画面でラテン文字のフォントが混ざっている。原因は Zen Kaku Gothic New・Klee One にベトナム語の声調つき文字が無く、無い字だけが別のフォントに落ちること（ハングル・デーヴァナーガリー・ミャンマー文字・簡体字の一部も同じ）。言語ごとに Google Fonts の本文の書体を足し（ベトナム語 Be Vietnam Pro、中国語 Noto Sans SC、韓国語 Noto Sans KR、ネパール語 Noto Sans Devanagari、ミャンマー語 Noto Sans Myanmar）、Chrome の CDP で「実際に使われた字体」を取って、全言語でシステムのフォントに落ちる字が無いことを確かめた。
- 作り手の判断: 手書きの書体（Klee One）は、赤ペンとして入る日本語だけ。他の言語の画面の言葉（ラベル・見出し）は、その言語の本文の書体で出す。

## 11/7（土）

- 名前を「JAWS 日本語じょうず」（英語: JAWS: Nihongo Jozu）に。「日本語上手ですね」と言われない日のために、という導入とつながる。
- Cloudflare Workers に公開した。つまずき: Claude のクラウド環境のプロキシが `api.cloudflare.com` 向けの `Authorization` を上書きするため、静的ファイルのアップロード（一時的な JWT）だけ 401 になる。GitHub Actions から push のたびにデプロイする形にした。
- 作り手の動機: 外国人住民のコミュニティに出向いて試してもらいたい。もう一つ、デモ動画は声を前もって録ったものなので、本当に生成しながらで実用に耐えるか不安 → 実環境で測った。相手の返事まで 4.5〜5秒（文字起こし 0.6秒・相手役 1.5〜2秒・読み上げ 2.2秒）。赤ペン 11秒、カンペ 15秒は1回だけ。
- 縦画面の録画で見つけた不具合2つ（画面の切り替えでスクロール位置が残る、カンペの見出しが鍵の名前のまま）を直した。
- 作り手が公開 URL で試した: 応答の速さは十分。直した所: 赤ペンの生成中の見出し（「…つ」→「…」）、相手役が会話を終えた瞬間に赤ペンを裏で始める（押したときには出来ている）、言語選択の矢印のずれ。
- QR が細かすぎて読めなかった（カンペの中身を URL に詰めていたため）。作り手の案で、Gyazo と同じく推測できない ID でサーバー（KV）に置き、短い URL を QR にする形に変えた。30日で消える。
- 初級の人（Ship It Saturdays のメンバー）に試してもらったら「そもそも何を話せばいいか分からない」と言われた。練習の画面は「言う材料（名前・住所）」は出していたが「何を・どの順で聞かれるか」を出していなかった。場面カードの「本番で聞かれること」（Can do の文に書かれた伝えることを、受付が聞く順に並べたもの。相手役とカンペはすでに使っていた）を、練習の画面の横に、練習用の答えを添えて出すようにした。見出しは9言語に訳した。
- 作り手が「赤3つは少ない気がする」。仮の正解を数えると赤は1本あたり0〜3つで、上限に当たったのは1本だけ。少なく見えるのは4つ目以降が「今は直さなくていいこと」に入って折りたたまれていたからなので、初めから開いて見せ、上限を4→6にした（指示 2026-11-07.1、評価の結果は .2 と同じ範囲）。
- 作り手が中国語・ベトナム語・英語の画面で見て: 聞かれることの見出しに日本語が残っていた → 日本語以外（やさしい日本語も）は訳だけにした。病院の「用件（どんなことで）」は、Can do の文にある「診察理由」に。
- 練習で名乗る名前が、どの言語でも同じ国の名前（グエン・ラン など）だった → 名前（本人・子ども・配偶者）を画面の言語ごとに差し替える変数にした（`shared/persona.ts`）。場面カード50枚の名前を 〔名前〕 に置き換え、文字起こしの語も言語に合わせて埋める。住所・電話番号は共通のまま。練習用の情報の見出しも9言語に訳した。
- 提出準備のセッションからの申し送り（英語の画面の試し撮りで見つかった所）を直した: 「3items」→「3 items / 1 item」（数の入る言葉を {n} 付きの鍵にして10言語に手で入れた）、「Red pen（2Try #）」→「Red pen (Try 2)」、英語の文と日本語の文の間の空白、「ぶっきらぼう「お金は？」」の間の空白、「（2）」→「 (2)」、カンペの「赤ペン」の札を画面の言語に。
- 試し撮りで、2回目の赤ペンの前回の判定が3つとも △「この場面が出てきませんでした」になった件: 前回の引用と Claude の返事を文字どおりでしか対応づけていなかったので、句点やかぎかっこが変わると全部 △ に落ちていた。記号を除いた比較と、数が同じなら順番で対応づける形に（`matchRetry`、テスト付き）。指示は変えていない（同じ会話で2回試して、Claude の判定そのものは ○△ とも正しかった）。
- 文字起こしが失敗したとき（クレジット切れなど）は、キーボード入力を自動で開いて「声の文字起こしが使えません。キーボードで入力してください」と出す。
- 試し撮りで、学習者の「来週の火曜日は、いいですか？」に受付役が「11月の何日でしょうか」と聞き返した。相手役は今日の日付を知らなかった。確かめると、相対的な日を一度も日付に直せず（16回中0回）、場面カードの例「11月18日の火曜日」を写していた（2026年の18日は水曜日）。今日の日付とカレンダーを渡すと、16回とも正しい月日と曜日で確かめた（指示 2026-11-07.2）。場面カードの日付で、実際の暦とぶつかるものも直した。
- 作り手に「評価の正解をどう確かめればいいか」と聞かれ、確かめる道具を作った（公開先の `/dev/gold`）。会話ごとに赤（多くても3つ、直す順）と「直さない」所を入れ直し、最新の評価で Claude が入れた赤と並べて食い違いを見る。判断の理由はメモに書ける。書き出した JSON を `scripts/apply-gold.ts` で正解に入れる。先生の判断を、評価のデータとして残すための道具。
- README を審査向けに書き直した。
